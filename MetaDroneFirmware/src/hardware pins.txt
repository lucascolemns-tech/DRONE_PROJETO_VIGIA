META DRONE FIRMWARE - HARDWARE CONNECTIONS AND MAIN STRUCTURE
Board targets configured in platformio.ini:
  STM32: WeAct Studio BlackPill V2.0, STM32F411CE
  ESP32: DOIT ESP32 DEVKIT V1

ESP32 CONNECTIONS
-----------------
ESP32 GPIO16 RX <- STM32 PA9 TX
ESP32 GPIO17 TX -> STM32 PA10 RX
Connect STM32 GND and ESP32 GND together. UART is 115200 baud, 8 data bits,
no parity, 1 stop bit. Cross TX to RX as shown; do not connect TX to TX.

The ESP32 connects to the configured Wi-Fi network and serves TCP port 1244.
The firmware static IP is 10.85.164.132; the Python interface default matches.
Wi-Fi credentials are currently set in src/INTERNET/INTERNET_ESP.cpp. The current
firmware/interface use Wi-Fi TCP; there is no Bluetooth command path in this code.

POWER AND SIGNAL NOTES
----------------------
All grounds must be common between the controller boards, sensors, and ESC signal
ground. STM32 GPIO is 3.3 V logic; verify every sensor/module UART level before
connecting and use level shifting for any 5 V logic output. Power motors from the
appropriate separate ESC/battery supply, not from STM32 GPIO or its 3.3 V rail.
ESC signals are 50 Hz pulses, constrained in firmware to 1050-2000 us.
I2C pull-ups must be to 3.3 V and the bus must not have excessive parallel pull-ups.
The magnetometer should be mounted with its X/Y/Z axes aligned to the MPU axes,
away from motors, high-current wiring, steel, and other magnetic interference.

PIN CONFLICTS / RESERVATIONS
---------------------------
PA11 and PA12 are also USB OTG FS D-/D+ on the BlackPill. Firmware assigns them
to GPS USART6, so USB data cannot be used concurrently while that UART is wired.
Use ST-Link for programming/debugging with GPS connected, or move GPS to another
verified free UART pin pair before using USB data.

The BlackPill build enables USB CDC with USBCON and USBD_USE_CDC, so Arduino
Serial debug output uses USB on PA11/PA12 and remains separate from USART1 on
PA9/PA10 used by the ESP32 link. STM32 debug is enabled with STM32_DEBUG_UART.
USAR_GPS is disabled in the current build; a GPS physically connected to PA11/PA12
must be disconnected while using the BlackPill USB debug connection.

MAIN FIRMWARE STRUCTURE
-----------------------
1. Python interface connects over TCP to the ESP32 at 10.85.164.132:1244.
2. ESP32 validates four text setpoints and sends six float values to STM32:
   roll, pitch, yaw turn-rate command, throttle, command-fresh flag,
   magnetometer-calibration request. Binary frame: AA 55 + 24 payload bytes
   + 2 CRC-16 bytes (28 bytes total).
3. STM32 checks finite/range/neutral conditions, reads sensors, fuses MPU6500
   gyro/accelerometer with calibrated magnetometer using Madgwick MARG, and
   runs the attitude PID only while all arming/failsafe checks pass.
4. STM32 returns 15 floats to ESP32: roll, pitch, magnetic yaw, altitude,
   vertical velocity, temperature, four motor outputs, battery voltage, GPS
   altitude, sensors-ready flag, magnetometer status, calibration progress.
   Binary frame: AA 55 + 60 payload bytes + 2 CRC-16 bytes (64 bytes total).
5. ESP32 forwards 16 comma-separated telemetry values to Python: the 15 STM32
   values plus a fresh-link flag. Python validates and displays the data.

STARTUP / ARMING / CALIBRATION
-----------------------------
- ESC outputs initialize at minimum pulse width (1050 us).
- STM32 initializes MPU6500 over SPI, barometer/INA219/magnetometer/VL53L0X over
  I2C, and GPS over USART6. MPU6500, BMP388, INA219, and magnetometer are the
  arming-required sensors; GPS and VL53L0X are not arming gates in the current code.
- Magnetometer calibration is requested from the Python interface with props
  removed. Keep away from metal and rotate the assembled drone through all axes
  for about 25 seconds. The calibration result is stored in STM32 EEPROM.
- Arming requires fresh centered controls, a calibrated/live magnetometer,
  required sensors, valid battery voltage, and the existing neutral confirmation.
- Yaw telemetry is magnetic heading (not declination-corrected true north).
  The yaw control is a turn-rate command; centered yaw holds the captured heading.
- Stale control/sensor data or invalid operating state returns outputs to minimum.

VERIFICATION SCOPE
------------------
Source pin assignments and protocol sizes are recorded from the current firmware
and BlackPill F411 variant. A successful PlatformIO build and offline protocol/
interface simulations do not prove physical wiring, sensor orientation, compass
accuracy, ESC direction, or flight stability; verify those with props removed.
